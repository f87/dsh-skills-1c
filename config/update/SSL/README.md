# SSL — специфика 1С:Библиотеки стандартных подсистем (БСП)

Подраздел `config\update\SSL\` — для правил, которые **не универсальны для любой 1С**, но универсальны
для конфигураций на **БСП** (ЕРП, УТ, УПП, УАТ, БП и большинство типовых решений). Отдельная папка —
потому что имена объектов, механизмы и гейты здесь диктует БСП, а не платформа.

Если конфигурация не на БСП — файлы раздела не применяются (или адаптируются под свой аналог).

| Файл | О чём |
|---|---|
| [`predefined.md`](predefined.md) | `Predefined.xml` каталогов БСП (`ИдентификаторыОбъектовМетаданных`, `НаборыДополнительныхРеквизитовИСведений`): слияние, дубли `<Item id>`, имена без объекта |
| [`access-lists.md`](access-lists.md) | списки ограничения доступа: `ПриЗаполненииОграниченияДоступа`, `Списки.Вставить(Метаданные.X, …)`, проверка |
| [`exchange-plan-content.md`](exchange-plan-content.md) | план обмена «Интеграция с 1С:Документооборотом»: состав плана должен покрывать определяемые типы БИД |

## Инструменты (в этом каталоге)

| Инструмент | Назначение |
|---|---|
| `regmerge.js` | слияние `Predefined.xml` по `<Item id>` и имени + фильтр orphan; режим `types` — вспомогательное слияние `<Type>` из донора (универсальное объединение типов — `config/update/mergetypes.js`) |
| `checkpredefined.js` | гейт: `lost=0`, `duplicateIds=0`, `orphanNames=0` |
| `checkaccesslists.js` | гейт списков ограничения доступа; `EXIT 2` = строковых ссылок нет, нужна ручная проверка `Метаданные.*` |
| `checkplancontent.js`, `fixplancontent.js` | проверка и починка состава плана обмена БИД |

```powershell
node config\update\SSL\regmerge.js <tree> <donor> predefined <report.json>
node config\update\SSL\checkpredefined.js <result> <vendor> <report.json>
node config\update\SSL\checkaccesslists.js <result>
node config\update\SSL\checkplancontent.js <tree>
```

## Почему это отдельный раздел

- **Имена** (`ИдентификаторыОбъектовМетаданных`, `НаборыДополнительныхРеквизитовИСведений`,
  `УправлениеДоступомПереопределяемый`, план «Интеграция с 1С:Документооборотом») — из БСП, их нет
  в платформе и в конфигурациях без БСП.
- **Механизмы** (предопределённые идентификаторы метаданных, ограничения доступа на уровне записей,
  БИД) — тоже БСП.
- Ошибки здесь **не видны** ни при загрузке в пустую базу, ни в `CheckModules` — только в рантайме или
  на базе с данными. Поэтому у раздела свои обязательные гейты.
