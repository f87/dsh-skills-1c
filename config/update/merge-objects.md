# Слияние элементов объектов (реквизиты, ТЧ, формы, макеты, команды)

Реализация: `config\update\objmerge.js` + `config\update\syncobjfiles.js`.

## Модель

Для объекта, который есть в обеих версиях: `base` = новая поставка, `old` = предыдущая поставка,
`ours` = текущая конфигурация. Добавляем в `base` дочерние элементы, которые есть в `ours`, но которых нет
ни в `old`, ни в `base`. Совпадение — по имени и/или uuid, дубли не создаются.

```powershell
node config\update\objmerge.js <base.xml> <old.xml> <ours.xml> <out.xml>   # отчёт — JSON рядом
node config\update\syncobjfiles.js <resultTree> <currentTree> <baseTree>   # файлы форм/макетов
```

`syncobjfiles.js` читает `<Form>`/`<Template>` из XML объектов и копирует отсутствующие файлы из доноров.
**Не путать** с `<Template>` внутри HTTP-сервисов (`/rpc`, `/version`) — это не макеты (в проекте было
65 ложных срабатываний).

## Объекты, которых нет в поставке

Копируются целиком (`skel.js`/`copyfrom.js`) — `objmerge` для них не нужен.

## Что НЕ переносим

- «Наши» изменения свойств объекта (порядок, комментарии) — обычно артефакты выгрузки.
- Дубли реквизитов, которые поставщик переименовал в `Удалить…` с тем же UUID — только переименование
  ссылок (`renames-refs.md`).
- Правки `Configuration.xml` вручную там, где работает `addchild.js`.

## Грабли реализации (исправлено 21.10.2026)

1. **`addchild.js` добавлял в `<ChildObjects>` тег `Configuration`.** Имя из списка вида
   `Configuration.МодульX` превращалось в `<Configuration>МодульX</Configuration>`, и 1С падала:
   «объект метаданных Configuration не был загружен, поскольку не является подчинённым».
   Теперь такие имена пропускаются и считаются в `skippedNotSubordinate`.
2. **`objmerge.js` создавал дубль элемента с тем же `uuid`.** Если поставщик переименовал реквизит с
   сохранением `uuid` (`X` → `УдалитьX`), наш элемент с именем `X` не совпадал по ключу и вставлялся
   вторым — 1С: «Имя реквизита или поля … не уникально». Теперь элемент, `uuid` которого уже есть в
   `base`/`old`, не добавляется (`skippedExisting`).

Проверка: фикстуры `..\_work\audit_skills\` — до патча `added=3` с тегом `Configuration` и 2 элемента
с одним `uuid`; после — `added=2, skippedNotSubordinate=1` и `added=0, skippedExisting=1`.

### Известное поведение (не дефект)

- Оба скрипта вставляют элементы **в конец** `<ChildObjects>`, а не в группу своего типа (R08:
  `Attribute → Form → TabularSection → Command`). 1С принимает, но её выгрузка переставит элементы —
  для побайтных диффов элементы в группу ставьте вручную/после выгрузки.
- `objmerge.js` пишет вставляемый блок с `\n`, выгрузка 1С — `\r\n`; на содержимое не влияет, даёт
  байтовые отличия.

## Проверка

1. Отчёт `objmerge`: сколько элементов добавлено по каждому объекту; повторный запуск — 0.
2. В результатах нет XML-дублей: одинаковые `<Name>`/uuid внутри объекта.
3. После загрузки нет сообщений `Неверный путь к данным` (неправильно вставленный `<Type>`/атрибут) и
   `Файл объекта не существует <объект>/Forms/<имя>.xml` (забыли `syncobjfiles`).
4. Формы открываются (см. `check-forms.md`).

## Типовые ошибки и причина

| Ошибка | Причина |
|---|---|
| `Файл объекта не существует …Forms\X.xml` | элемент добавлен в XML, файл не скопирован |
| `Имя реквизита или поля X не уникально` | добавлен дубль реквизита с тем же UUID |
| `Неверный путь к данным` | в форму попал `<Type>`/атрибут из чужого блока (см. `defined-types.md`) |
