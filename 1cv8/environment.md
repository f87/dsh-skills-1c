# Окружение

Проверено Октябрь 2026: Windows, PowerShell 7.5.5, node 24.21.0, платформа **8.3.27.1859** (пример проверки,
не требование).

## Платформа

**Подходит любая установленная версия `8.3.27.*`** (и ниже — если формат выгрузки вашей версии совместим,
см. «Формат выгрузки»). Привязки к конкретному билду нет: путь к `1cv8.exe` определяется на машине.

```powershell
# самый свежий установленный 1cv8.exe в стандартных каталогах
$exe = @('C:\Program Files\1cv8', 'C:\Program Files (x86)\1cv8') |
  Where-Object { Test-Path -LiteralPath $_ } |
  ForEach-Object { Get-ChildItem -LiteralPath $_ -Directory } |
  Sort-Object { try { [version]$_.Name } catch { [version]'0.0' } } -Descending |
  ForEach-Object { Join-Path $_.FullName 'bin\1cv8.exe' } |
  Where-Object { Test-Path -LiteralPath $_ } | Select-Object -First 1

"$exe"
(Get-Item -LiteralPath $exe).VersionInfo.FileVersion
```

Нужна конкретная версия — подставьте путь `...\1cv8\<версия>\bin\1cv8.exe` вручную. Дальше во всех
примерах используется переменная `$exe`.

| Что | Значение |
|---|---|
| Платформа | любая `8.3.27.*` и ниже; путь — через `$exe` (выше) |
| Лицензия | служба `hasplms`; несколько сессий Конфигуратора одновременно допустимы |
| SQL | локальный `MSSQLSERVER`; внешние базы по SSPI/шифрованию могут быть недоступны из сессии |
| OneScript | `oscript.exe` часто **не в PATH** — вызывать по полному пути |
| node | 20+ в PATH — на нём написаны вспомогательные скрипты |
| Ресурсы (пример) | 190 ГБ RAM, 16 логических ядер, ~2 ТБ свободно на рабочем диске |
| Диски (пример) | XML-дерево крупной конфигурации ≈ 8–11 ГБ / 120–128 тыс. файлов; файловая база ≈ 1,6 ГБ |

## Формат выгрузки и версия платформы

- `Configuration.xml` и остальные XML содержат атрибут `version` (например, `2.20` для 8.3.27) и набор
  свойств, зависящий от версии платформы. При переходе на другую версию **не полагайтесь на шаблоны из
  этих скилов** — берите структуру из свежей выгрузки той же платформы (`config/dump-to-xml.md`).
- `ConfigDumpInfo.xml` и `Ext\ParentConfigurations.bin` стабильны, но проверяйте разбором, а не по памяти.
- Расширения (`.cfe`), EDT-проекты (`*.mdo`) и хранилище конфигурации в скилах не рассматриваются.

## Совместимость версий

- `.cf`/`.cfu`/`.dt` и XML-выгрузка версионны: файл, созданный платформой N, штатно читается платформой
  **N и новее**. Более старая платформа обычно отказывается («несовместимый формат»).
- Поэтому «в скилах указан билд X, а установлен Y» — не проблема, если **Y не ниже** версии, которой
  создана конфигурация/файл. Обратный случай (файл новее платформы) решается только обновлением платформы.
- XML лучше выгружать той же версией, которой будете загружать: тогда атрибут `version` и набор свойств
  совпадут, а диффы будут чистыми.
- Проверка всегда одна: `CREATEINFOBASE` + `LoadCfg`/`LoadConfigFromFiles` → EXIT 0 и «Загрузка
  конфигурации успешно завершена» в `/Out`-логе.

## Замеры (для планирования; пример — крупная и малая конфигурации)

| Операция | Время |
|---|---|
| `CREATEINFOBASE` | 2 с |
| `LoadCfg` 1,5–2,4 ГБ | 1,5–3 мин |
| `LoadCfg` 4 ГБ | 2,7 мин |
| `DumpConfigToFiles` крупной конфигурации | 10–12 мин |
| `LoadConfigFromFiles` (полная сборка, 120+ тыс. файлов) | **38–49 мин** |
| `CheckModules -ThinClient` | 8,5 мин |
| `DumpCfg` | 35 с |
| `LoadCfg` готового `.cf` (1,5 ГБ) | 1,6 мин |
| **малая конфигурация** (дерево ~12,7 тыс. файлов): `LoadConfigFromFiles` | 78–120 с |
| то же: `DumpConfigToFiles` | 22–27 с |
| то же: `DumpCfg` | 4 с |

«Малая конфигурация» — быстрый цикл проверки правок выгрузки (поддержка, реквизиты, объекты): полный
круг «загрузка → выгрузка» укладывается в 2–3 минуты, что позволяет проверять гипотезы экспериментом,
а не по памяти.

## Раскладка рабочего каталога (пример)

```
<работа>\
  CF\        входные .cf/.cfu и готовые результаты
  src\       XML-деревья (current, vendor, update, result_*)
  _work\     файловые базы ib_*, логи, манифесты, списки, отчёты
  *.md       промт/отчёт задачи
```

## Пример проекта (не требование)

Проект, на котором проверялись скилы: обновление ERP 2.5.27.98 + модуля УАТ. Для него поставщик требовал
платформу не ниже 8.3.27.1859 (рекомендовал 8.3.27.1989+). Это ограничение **конкретной поставки**, а не
этого хранилища.

## Песочница (DSH/агент)

Для запуска `1cv8.exe` нужен полный доступ к файловой системе (danger-full-access): в ограниченной
песочнице процесс падает при старте с `System.NullReferenceException … OneSexLib.Exports.SCOM_Main`
(код `-532462766` = `0xE0434352`). Это не ошибка конфигурации и не повод менять команду.
