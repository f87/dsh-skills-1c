# Проверка форм

## Что проверяем

1. **Файл формы существует** и XML валиден (все `<Form>`-ссылки объекта имеют файл
   `<объект>\Forms\<Имя>.xml`).
2. **Пути к данным** в форме корректны: реквизиты, на которые ссылается форма, есть у объекта и в нужном
   типе (ошибка загрузки `Неверный путь к данным`).
3. **Нет дублей** реквизитов формы/объекта (`Имя реквизита или поля X не уникально`).
4. **Модуль формы компилируется** (`CheckModules -ThinClient -Server` — синтаксис всех модулей, включая формы; см. `config/checkmodules.md`).
5. **Форма открывается** в пользовательском режиме (ручная/автоматическая проверка ключевых форм).

## Как проверять автоматически

```powershell
# 1) все ссылки на формы/макеты имеют файлы
node config\update\syncobjfiles.js <tree> <currentTree> <baseTree>   # в отчёте — missing

# 2) загрузка в пустую базу: в логе не должно быть
#    "Файл объекта не существует …Forms\…xml" и "Неверный путь к данным"
& $exe DESIGNER /F"<ib>" /LoadConfigFromFiles"<tree>" /Out"<log>" /DisableStartupDialogs /DisableStartupMessages

# 3) синтаксис модулей (включая модули форм)
& $exe DESIGNER /F"<ib>" /CheckModules -ThinClient -Server /Out"<log>" /DisableStartupDialogs /DisableStartupMessages
```

В Конфигураторе дополнительно: `Конфигурация → Проверка конфигурации` (проверяет ссылки, формы, права;
на больших конфигурациях идёт долго) и открытие форм в отладчике.

> Честно: в проекте ERP 2.5.27.98 полная «Проверка конфигурации» не запускалась — использовались загрузка
> + `CheckModules` + выборочное открытие форм. Если позволяют ресурсы, прогоняйте её перед сдачей.

## Типовые причины ошибок

| Сообщение | Причина | Лечение |
|---|---|---|
| `Файл объекта не существует <объект>/Forms/X.xml` | форма добавлена в XML объекта, файл не скопирован | `syncobjfiles.js` |
| `Неверный путь к данным` | в форму вставлен `<Type>`/атрибут из чужого блока; переименован реквизит | не сливать типы по блоку; переименовать ссылки (`renames-refs.md`) |
| `Имя реквизита или поля X не уникально` | дубль реквизита с тем же UUID (обычно при «ручном» добавлении удалённого поставщиком) | удалить дубль, переименовать ссылки |
| `Неизвестный объект метаданных - Catalog.X.Attribute.Y` | форма ссылается на переименованный реквизит | переименовать в `УдалитьY`/новое имя |

## Слияние форм

- Если поставщик **не менял** форму (файл в `ours` = файл в `old`), можно взять нашу версию.
- Если менял — сливать **элементы** (objmerge), а не заменять файл целиком: иначе теряются изменения
  поставщика (новые реквизиты, команды).
- Новые формы из `current` копировать вместе с каталогом `Forms\<Имя>` (модуль, справка) и добавлять
  `<Form>` в XML объекта.
- Не заменять `FilterCriteria/СвязанныеДокументы.xml` версией другого модуля — там ссылки на удалённые
  реквизиты (проверено: 174 «неизвестных объекта»).

## Ручная проверка после загрузки (минимум)

- формы объектов УАТ, затронутых обновлением;
- формы ЭПД/ЭДО (электронные перевозочные документы);
- `РегистрСведений.НаличиеФайлов` — форма и измерение `ОбъектСФайлами` (тип `ВладелецПрисоединенныхФайлов`),
  это индикатор корректности `config/update/defined-types.md`.
