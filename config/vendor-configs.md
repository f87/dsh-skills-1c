# Поставки в XML-выгрузке: `Ext\ParentConfigurations\*.cf` и вычисление дельты

Универсально: любая конфигурация на поддержке, любая платформа `8.3.27.*` и ниже.

Правило едино **и для текущей версии конфигурации, и для конфигурации после обновления**.

---

## 1. Где лежат конфигурации поставщиков

В XML-выгрузке конфигурации, стоящей на поддержке, копии поставок лежат в:

```
<tree>\Ext\ParentConfigurations\<ИмяПоставки>.cf
```

- **Число файлов = число поставок** (поставщиков). Обычно один, но бывает несколько
  (пример: основная конфигурация + подключаемый модуль).
- **Имя файла = имя поставки** — то же, что поле «имя» в дескрипторе `Ext\ParentConfigurations.bin`
  и то же, что в `Configuration.xml` самой поставки после выгрузки.
- Рядом с `.bin` эти файлы — **копия версии поставщика**, а не наша конфигурация и не наш результат.

Проверено 27.10.2026:

| Дерево | `.cf` в `Ext\ParentConfigurations` | Поставок в `.bin` |
|---|---|---|
| демо-выгрузка на поддержке | 1 (`БиблиотекаСтандартныхПодсистемДемо.cf`, 98 МБ) | 1 |
| реальная конфигурация «ЕРП + модуль УАТ» | 2 (`УправлениеПредприятием.cf` 2 256 МБ, `МодульУправлениеАвтотранспортомДля1СERP.cf` 27 МБ) | 2 |
| собранный результат (одна поставка) | 1 | 1 |
| чистая выгрузка поставки (`vendor_erp`, `update_erp`) | каталога нет | 0 |

**Когда каталога нет:**

- конфигурация **не на поддержке** (чистая выгрузка поставки) — сам `.cf` и есть поставка, берите его из
  комплекта поставки;
- конфигурация **на полной поддержке** (флаг `1` в `.bin`) — 1С не хранит копии
  (`config/support-state.md`, §4.4). Возьмите `.cf` из комплекта поставки той версии, что указана в
  дескрипторе `.bin`.

## 2. Поставки нужно выгрузить в XML

Дельта считается по **XML-деревьям**, поэтому каждый `.cf` из `Ext\ParentConfigurations` выгружается
в собственное дерево — **каждый в свою чистую базу** (иначе получите смесь объектов).

```powershell
$exe     = '<каталог платформы>\bin\1cv8.exe'      # 1cv8/environment.md
$tree    = '<tree>'                                 # наша выгрузка
$vendorDir = Join-Path $tree 'Ext\ParentConfigurations'
$work    = '<work>\vendor'

Get-ChildItem -LiteralPath $vendorDir -Filter *.cf | ForEach-Object {
  $name = [IO.Path]::GetFileNameWithoutExtension($_.Name)
  $ib   = Join-Path $work "ib_$name"
  $dst  = Join-Path $work $name
  Remove-Item -LiteralPath $ib, $dst -Recurse -Force -ErrorAction SilentlyContinue
  New-Item -ItemType Directory -Force $ib | Out-Null

  & $exe CREATEINFOBASE "File='$ib'" /Out"$work\$name.create.log" /DisableStartupDialogs /DisableStartupMessages
  & $exe DESIGNER /F"$ib" /LoadCfg"$($_.FullName)" /Out"$work\$name.load.log" /DisableStartupDialogs /DisableStartupMessages
  & $exe DESIGNER /F"$ib" /DumpConfigToFiles"$dst" /Out"$work\$name.dump.log" /DisableStartupDialogs /DisableStartupMessages
}
```

Проверка каждой выгрузки: в `$dst\Configuration.xml` — `<Name>`, `<Version>`, `<Vendor>`; они должны
совпадать с именем файла и с дескриптором в `Ext\ParentConfigurations.bin`
(`config/support.md`, §4).

Пример объёмов (октябрь 2026): `.cf` 2,36 ГБ → `LoadCfg` 97 с, `DumpConfigToFiles` 647 с (8,5 ГБ,
121 712 файлов); `.cf` 3,98 ГБ → 162 с и 739 с (10,9 ГБ, 128 668 файлов).

## 3. Формула дельты

```
[Наши доработки] = [Текущая рабочая конфигурация] − [ВСЕ конфигурации поставщиков]
```

Раскрывается по объектам метаданных:

- **объект в дельте (доработка)**, если его файлы не совпадают **ни с одной** поставкой;
- **объект собственный**, если его нет **ни в одной** поставке (в дельту входит по определению);
- **объект типовой**, если он побайтно совпал хотя бы с одной поставкой — даже если вторая поставка его
  не содержит;
- сравнение — по содержимому файлов (SHA1), а не по `configVersion` и не по уровню поддержки.

Поставки объединяются именно **объединением**: при нескольких поставщиках нельзя считать дельту по одной
из них — объекты второй попадут в «доработки» (или наоборот, типовой объект будет считаться изменённым).

## 4. Инструменты

```powershell
# дельта: текущая конфигурация и результат после обновления против ВСЕХ поставок
node config\update\delta-check.js <currentTree> <resultTree> `
     <vendor>\УправлениеПредприятием <vendor>\МодульУправлениеАвтотранспортомДля1СERP

# точечно: какие объекты отличаются от конкретной поставки
pwsh -File config\support-state.ps1 -Tree <tree> -Compare <vendor>\УправлениеПредприятием
```

`delta-check.js` принимает список поставок и считает объект типовым, если он совпал с любой из них
([`update/delta-invariance.md`](update/delta-invariance.md)).

## 5. Правило одинаково до и после обновления

1. **До обновления**: выгрузить поставки из `Ext\ParentConfigurations` текущей конфигурации, посчитать
   `Δ_before = current − ∪ vendor_before`.
2. **После обновления**: взять поставки из `Ext\ParentConfigurations` **результата** (там уже новые
   версии), посчитать `Δ_after = result − ∪ vendor_after`.
3. Сравнить: `Δ_after` должен совпасть с `Δ_before` — это инвариант дельты
   ([`update/delta-invariance.md`](update/delta-invariance.md)). Допустимые отклонения — удаление
   объекта поставщиком (в отчёт) и постановка на поддержку объекта, который был снят, но не изменён.

Важно: сравнивать нужно с **поставками того же дерева**, а не с поставками «другой стороны». Если брать
`vendor_before` для `Δ_after`, любая правка поставщика в новом релизе будет выглядеть как наша доработка.

---

## 6. Грабли

- **Каталог `Ext\ParentConfigurations` — не наша конфигурация.** Это копии поставок; не путать их с
  `*.cf`, собранным из результата.
- **Число файлов = число поставок**, но имя файла может не совпадать с «ожидаемым» — сверяйте с
  дескриптором в `.bin` (`config/support.md`, §4), а не по памяти.
- **При полной поддержке каталога нет** — берите `.cf` из комплекта поставки, версия должна совпадать
  с дескриптором `.bin`.
- **Каждую поставку — в отдельную чистую базу.** Две выгрузки в одну базу дают смесь объектов и ложную дельту.
- **Нельзя игнорировать вторую поставку** при расчёте дельты — иначе её объекты попадут в доработки.
- **Версия важнее даты файла**: в каталоге лежит та версия, на которой стоит конфигурация, а не «самая
  свежая от поставщика».
- `.cf` из каталога нельзя использовать как результат сборки — это только эталон для сравнения.
