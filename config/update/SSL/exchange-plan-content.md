# БСП: план обмена «Интеграция с 1С:Документооборотом» и определяемые типы

Класс ошибок, который **не виден** ни при загрузке в пустую базу, ни в `CheckModules`: типы объединены,
но состав плана обмена БИД остался от поставки. Проявляется только в обработчике обновления БИД при
первом запуске на базе с данными.

Раздел относится к конфигурациям на БСП (план и три определяемых типа — объекты БСП); для конфигурации
без БСП правило остаётся верным в общем виде, но константы скриптов нужно заменить.

---

## 1. Правило

Если объект входит в **определяемый тип**, который используется планом обмена (или подсистемой обмена),
этот объект должен быть в **составе плана** (`ExchangePlans\<План>\Ext\Content.xml`).

Симптом (пример — БСП «Интеграция с 1С:Документооборотом»):

> Тип "ДокументСсылка.…" выбран в определяемом типе "…", но отсутствует в составе плана обмена "…"

`mergetypes.js` добавляет типы в `DefinedTypes\*.xml`, но `Content.xml` плана не трогает — отсюда
рассогласование.

## 2. Что проверять

Для каждого плана обмена, зависящего от определяемых типов:

1. Собрать объединение типов из `DefinedTypes\<Тип>.xml`, которые «питают» план (в проекте — 3 типа БИД:
   `…ВсеСсылки…`, `…ДокументыОбъекты…`, `…СправочникиОбъекты…`).
2. Собрать состав из `ExchangePlans\<План>\Ext\Content.xml` (`<xr:Item>`/`<xr:Object>`).
3. Разница = `missing` (в типах есть, в плане нет) и `extra` (в плане есть, в типах нет).

`missing` → обработчик обновления упадёт. `extra` — обычно безвредно, но требует объяснения.

## 3. Как починить

- добавить недостающие элементы в `Content.xml` (с атрибутами регистрации — `AutoRecord` и т.п.);
- источник атрибутов — `Content.xml` донора (текущей конфигурации) либо значения по умолчанию;
- после правки — повторная проверка (шаг 2) и загрузка.

Реализация: `checkplancontent.js` (гейт) и `fixplancontent.js` (починка, `--apply`) — в этом каталоге;
имена плана и типов вынесены в константы в начале файлов, для другой конфигурации их надо заменить.

```powershell
node config\update\SSL\checkplancontent.js <tree>                    # EXIT 1, если есть missing
node config\update\SSL\fixplancontent.js <tree> <donorTree> --apply  # добавить недостающие
```

## 4. Почему это отдельный гейт

- `CheckModules` проверяет **компиляцию**, а не согласованность метаданных;
- `mergetypes.js` проверяет только сам `DefinedTypes`, не план;
- загрузка в пустую базу проходит (обработчик обновления не запускается);
- ошибка вылезает на базе **с данными** при обновлении — самом дорогом месте.

## 5. Гейт

| Проверка | Критерий |
|---|---|
| `checkplancontent.js <tree>` | `missing = 0`, EXIT 0 |
| после `fixplancontent.js --apply` | повторный `checkplancontent` — 0 |
| загрузка + `CheckModules -ThinClient -Server` | EXIT 0 |
| приёмка на базе с данными | обработчик обновления проходит без «отсутствует в составе плана» |
