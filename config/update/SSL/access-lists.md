# БСП: списки ограничения доступа (RLS на уровне объектов)

БСП-механизм: в общем модуле `УправлениеДоступомПереопределяемый` перечислены объекты, для которых
строятся списки с ограничением доступа, а в **модуле менеджера** каждого такого объекта должна быть
процедура `ПриЗаполненииОграниченияДоступа`.

Ошибка «объект в списке, а метода нет» **не видна** ни `LoadConfigFromFiles`, ни `CheckModules`:
пустой модуль-заглушка (несколько байт BOM) синтаксически валиден. Проявляется в рантайме — при
обращении к списку.

---

## 1. Как задаются списки

В модуле `УправлениеДоступомПереопределяемый` встречаются **два способа**:

```bsl
// 1) строкой — разбирается автоматически
Списки.Вставить("Документ.ЗаказНаДоставку", Истина);

// 2) через метаданные — требует ручной проверки
Списки.Вставить(Метаданные.Справочники.Банки, Истина);
```

Автоматический гейт надёжно ловит **только первый** вариант. Второй — вне зоны его действия, и это
нужно явно сообщать, а не считать проверку пройденной.

---

## 2. Гейт

```powershell
node config\update\SSL\checkaccesslists.js <resultTree> [report.json]
```

| Код | Значение |
|---|---|
| `0` | все найденные строковые ссылки имеют метод `ПриЗаполненииОграниченияДоступа` |
| `1` | есть объекты без метода — **блокер** |
| `2` | строковых ссылок нет: проверьте `Списки.Вставить(Метаданные.…)` вручную |

Отчёт: `{ objects, missing, details: [{ object, present, empty }], warning }` —
`present=false` значит модуль менеджера отсутствует, `empty=true` — модуль пустой (заглушка).

---

## 3. Правило «неопределённость — не успех»

Эвристический гейт обязан возвращать отдельный код неопределённости (`EXIT 2`) и не считаться
пройденным, пока ручная проверка не выполнена. «0 найденных проблем» без пройденной проверки — не
результат: именно так пропускается дефект с `Метаданные.*`.

Ручная проверка: найти в `УправлениеДоступомПереопределяемый` все `Списки.Вставить(Метаданные.<Вид>.<Имя>…)`
и для каждого проверить наличие метода в модуле менеджера (или в модуле объекта — зависит от того,
как БСП вызывает заполнение).

---

## 4. Грабли

- Пустой модуль-заглушка проходит `CheckModules` — обязательна отдельная проверка наличия метода.
- Список может пополняться в подписках/обработчиках, а не только в `УправлениеДоступомПереопределяемый`;
  после обновления модуль может быть заменён версией поставщика — проверяйте, что наши списки на месте.
- Если объект удалён поставщиком — его строка в списке должна исчезнуть вместе с объектом,
  иначе список ссылается на несуществующий объект.
- `EXIT 2` без ручной проверки в отчёте = гейт не пройден (это фиксируется в приёмке).
