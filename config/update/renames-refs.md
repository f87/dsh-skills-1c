# Переименования поставщика и чистка ссылок

## Суть

В 1С объект опознаётся **UUID**. Поставщик, «удаляя» объект/реквизит, часто **переименовывает его с тем же
UUID** в `Удалить<Имя>`. Примеры из 2.5.27.98:

- `Catalog.Контрагенты.Attribute.НДСПоСтавкам4и2` → `УдалитьНДСПоСтавкам4и2`;
- `Document.ВнутреннееПотреблениеТоваров` → `Document.ВнутреннееПотребление`;
- `Document.РегистрацияНаработок` → `Document.НаработкаОбъектовЭксплуатации`;
- `Document.Бронирование` → `Document.ОперацияСЭлектроннымБилетом` (по UUID).

## Следствия

1. Нельзя добавлять «свой» реквизит с тем же UUID — 1С падает на уникальности имён в формах.
2. Нельзя копировать объекты ЕРП из поставки другого модуля (собрана на другой версии) — дубли `InternalInfo`:
   `Тип порождаемый объектом InternalInfo содержит не уникальное значение`.
3. Правильно — переименовывать **ссылки**, а не создавать дубли.

## Порядок

1. Карта `uuid → имя` для старой и новой версии (`manifest.js`).
2. Пары «старое → новое» = одинаковый UUID, разные имена (`_work\lists\removed_renames_ok.json`, 116 пар в проекте).
3. Замена **квалифицированная** (`multirename2.js`): для каждого типа свой набор префиксов
   (`CatalogRef`, `CatalogObject`, `Catalog`…), с границей слова. Только ссылки — **не** `<Name>`.
4. Точечные переименования реквизитов (`renamerefs.js`) с защитой уже переименованных (`Удалить`+имя).
5. Остаточные ссылки на реально удалённое — вычистить (`prunetypes.js`, `prunerefs.js`) и зафиксировать в
   отчёте (`broken_refs`).

```powershell
node config\update\multirename2.js <tree> <pairs.json>
node config\update\renamerefs.js  <tree> <староеИмя> <УдалитьНовоеИмя>
node config\update\prunetypes.js  <tree>
node config\update\prunerefs.js   <tree>
```

## Чего нельзя

- Заменять `>Имя<` по всему дереву: это ломает `<Name>` и `Configuration.xml` (симптом:
  `Файл объекта не существует …/УдалитьОперацииЗакрытияМесяца.xml`).
- Заменять простое имя без границ слова: `Бронирование` внутри `БронированиеSmartway`.
- «Восстанавливать» удалённые объекты, чтобы ссылки сошлись: даёт 1078 несоответствий планов.

## Проверка

- В логе загрузки нет `Неизвестный объект метаданных` для переименованных сущностей (допустимы единичные
  предупреждения для УАТ-ссылок — фиксируются в отчёте).
- Нет дублей `InternalInfo` и `Имя реквизита … не уникально`.
- `Configuration.xml` не содержит объектов без файлов (проверка `fixconfig.js`).
