# Формат XML-выгрузки конфигурации

`DESIGNER /DumpConfigToFiles"<каталог>"` создаёт дерево:

```
<tree>\
  Configuration.xml          # состав (ChildObjects), версия, поставщик
  ConfigDumpInfo.xml         # реестр: имя объекта / id / configVersion
  Ext\                       # модули конфигурации, ParentConfigurations.bin
  Catalogs\, Documents\, ... # объекты, каталоги во МНОЖЕСТВЕННОМ числе
```

## Имена

- В манифесте объект — в **единственном** числе: `Catalog.Номенклатура`, `Document.X.Attribute.Y`,
  `Document.X.Form.Y`, `Subsystem.A.Subsystem.B`.
- Каталог — во **множественном**: `Catalogs`, `Documents`, `ChartsOfCharacteristicTypes`.
  Соответствие «тег → каталог» определяется по корневому тегу файла объекта (`<Catalog uuid="…">`).
- Элементы объекта: `<каталог>\<Объект>\Forms\<Имя>.xml`, `Templates\<Имя>.xml`, `Commands\<Имя>.xml`.

## `ConfigDumpInfo.xml` и `configVersion`

- `configVersion` **не является хэшем содержимого** между разными деревьями: одинаковые файлы дают разные
  значения. Проверено: `CommonModules/ОбщегоНазначения/Ext/Module.bsl` побайтно совпадает, версии разные.
- Внутри одного дерева выгрузка детерминирована: повторный дамп того же `.cf` даёт 0 отличий.
- Для сравнения деревьев: `config/hash.js` (SHA1 по файлам) + `config/filediff.js`.

## `Ext\ParentConfigurations.bin`

- Лежит в `Ext\` (корневого файла нет).
- Формат — **текст** UTF-8 с BOM, одна строка:
  `{6,<флаг>,<кол-во поставок>,<uuid>,<флаг>,<uuid>,"<версия>","<вендор>","<имя>",<кол-во объектов>,<уровень>,<режим>,<uuid>,<uuid>,...}`.
- Содержит не только дескриптор родителя, но и **уровень поддержки каждого объекта** (0/1/2) — по нему
  и меняется состояние поддержки в выгрузке. Полный разбор формата и процедуры:
  [`support-state.md`](support-state.md), инструмент — [`support-state.ps1`](support-state.ps1);
  уточнения для нескольких поставок (раскладка токенов, хвост) — [`support-state.md`](support-state.md) §2,
  правила — [`supply/deliveries.md`](supply/deliveries.md).
- Примеры дескрипторов: ERP 2.5.27.98 — `"2.5.27.98","Фирма ""1С""","УправлениеПредприятием"` (~12 МБ);
  УАТ 2.5.22.1 — `"2.5.22.1","Фирма ""1С-Рарус""","МодульУправлениеАвтотранспортомДля1СERP"` (~0,85 МБ).
- Признака поддержки в XML объектов нет — только в `.bin` и `ConfigDumpInfo.xml`.
- Копия конфигурации поставщика — `Ext\ParentConfigurations\<ИмяПоставки>.cf` (число файлов = число поставок; как выгрузить в XML и считать дельту — [`vendor-configs.md`](vendor-configs.md)). 1С выгружает её, когда
  объекты не на полной поддержке; при полном замке файла нет (проверено 20.10.2026). Нужна для сравнения
  и восстановления поддержки.

## Практика

- Байтовые отличия XML между деревьями — часто артефакты (порядок атрибутов, отступы, пустые модули).
  Решения принимайте по **составу элементов** (тег + `<Name>`/uuid), а не по `diff` файла.
- Дерево крупной конфигурации (пример: ERP) ≈ 120–128 тыс. файлов, 8–11 ГБ; держите рядом `manifest.json` и `hash.json`.
