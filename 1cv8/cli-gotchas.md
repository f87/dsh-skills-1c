# Грабли CLI (1С + обвязка на PowerShell)

## 1С

1. **Лимит 200 сообщений.** `LoadConfigFromFiles`/`LoadCfg` прерывается, накопив 200 сообщений (в логе ровно
   200 строк, `EXIT 1`, время 1–2 мин). Значит: устранять нужно **все** классы ошибок, а не «важные».
   Признак: успешная загрузка идёт 38–49 мин, аварийная — 1–2 мин.
2. **Только `/Out`.** `1cv8.exe` — GUI; stdout не читается. Каждый вызов:
   `/Out"<лог>" /DisableStartupDialogs /DisableStartupMessages`.
3. **Кавычки и кириллица.** Пути с пробелами (`update ERP_2_5_27_98.cf`) — всегда в кавычках:
   `/LoadCfg"<путь>"`, `/F"<путь>"`.
4. **`/DumpCfg` без `/Out`** может «зависнуть» на диалоге — лог обязателен.
5. **Параллельность.** Несколько Конфигураторов можно запускать только на **разных** базах.
6. **Файловая база при выгрузке** занимает ~1,6 ГБ; при нехватке места `DumpCfg` падает без внятной ошибки.
7. **После `DumpCfg`** файл дописывается несколько секунд — размер/хэш снимать после завершения процесса.
8. **`CREATEINFOBASE` и pwsh 7.** Форма `"File=""<ib>"";"` не доходит до 1С: ответ «Неверные или
   отсутствующие параметры соединения с информационной базой», в каталоге остаются нулевые
   `1Cv8.1CD.cfl`, затем `LoadConfigFromFiles` говорит «Информационная база не обнаружена!».
   Рабочая форма — `"File='<ib>'"`. Проверено 20.10.2026 (pwsh 7.5.5, 8.3.27.1859), три варианта записи.
   После неудачи каталог базы удалить и создать заново.
9. **`& $exe` не ждёт завершения.** `1cv8.exe` — GUI-подсистема (PE subsystem=2): без пайпа PowerShell
   запускает процесс и идёт дальше, `$LASTEXITCODE` остаётся пустым (в сессии так «повисли» лаунчеры).
   Ждать: `Start-Process -Wait -PassThru` → `ExitCode`, либо пайп `| Out-Null` (проверено: загрузка с
   пайпом корректно ждёт 78 с).
10. **`ibcmd.exe` бесполезен в batch.** `--version`, `help`, `infobase --help` дают 0 байт вывода при
    любом редиректе. Для проверок — только `1cv8.exe DESIGNER` + `/Out`-лог.
11. **Ограниченная файловая песочница (DSH/агент).** `1cv8.exe` падает на старте:
    `System.NullReferenceException: Ссылка на объект не указывает на экземпляр объекта. в
    OneSexLib.Exports.SCOM_Main(...)`, код `-532462766` (`0xE0434352`). Это не лицензия и не ошибка
    команды — нужен полный доступ к файловой системе (`1cv8\environment.md`, «Песочница»).

## Проверка результата

```powershell
$p = Start-Process -FilePath $exe -ArgumentList $args -Wait -PassThru -NoNewWindow
"exit=$($p.ExitCode)"
Get-Content $log -Encoding UTF8 | Select-Object -Last 5   # и классификация по config/update/diagnostics.md
```

## PowerShell-ловушки (проверено болью)

1. **Имена регистронезависимы**: `$n` и `$N` — одна переменная.
2. **Не называйте функции `R`, `cat`, `man`, `history`, `h`** — конфликт с алиасами: `R` → `Invoke-History`,
   `man` → `Get-Help`, `h`/`H` → `Get-History` (реальный случай: `function H {…}` → «Cannot bind parameter
   'Id'» вместо вычисления хэшей). Симптом: «A positional parameter cannot be found».
3. **`$args` — автоматическая переменная.** Параметр функции нельзя называть `$args` (иначе 1С запускается
   без аргументов). Используйте `$argList`.
4. **`param()` — первой строкой файла**, иначе `The term 'param' is not recognized`.
5. **`"$n: ..."`** трактуется как переменная со scope — писать `"${n}: ..."`.
6. **Сложный `node -e "..."`** из pwsh ломается на кавычках — выносите в `.js`-файл.
7. **`write` не перезапишет** файл, изменённый внешней командой, — сначала прочитайте.

## Файловые операции

```powershell
robocopy <src> <dst> /MIR /NFL /NDL /NJH /NJS /NP /R:1 /W:1   # код 3 = есть копирование и удаление, это норма
```

- Перед удалением/перемещением проверяйте абсолютный путь.
- Не читайте XML дерева, пока 1С с ним работает.
