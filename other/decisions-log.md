## Решения после брака (Октябрь 2026)

| № | Решение | Факт |
|---|---|---|
| 30 | **Определяемые типы — только объединение с приоритетом текущей конфигурации**; ни один тип current не удаляется; новые типы поставщика — в конец; переименования по UUID (`config/update/defined-types.md`) | — |

| 32 | Проверка типов — обязательный этап приёмки **до** `DumpCfg`, независимо от успешной загрузки в пустую базу | — |
| 33 | Порядок типов — как в конфигурации БД (current), новые — в конец | — |
| 34 | Объект удалён и замены по UUID нет → тип не добавлять, но фиксировать в отчёте (`missing`), решение принимает человек | — |
| 35 | **Состояние поддержки править в XML-выгрузке** (`Ext\ParentConfigurations.bin`), а не только в Конфигураторе | Проверено 20.10.2026: `-EnableChanges`/`-Level` воспроизводят выгрузки 1С побайтно; уровни сохраняются после `LoadConfigFromFiles` и возвращаются в `DumpConfigToFiles` (`config/support-state.md`) |
| 36 | **`mergetypes.js`: не перезаписывать блок `<Type>`; дополнить карту суффиксов типов** | Патч перенесён 21.10.2026. До этого: 86 «Недопустимый тип» + 200 «Неверный путь» (потеря квалификаторов) и 12 типов-ссылок на отсутствующие объекты (`config/update/defined-types.md`) |
| 37 | **`addchild.js`: не добавлять `Configuration` в `ChildObjects`; `objmerge.js`: не дублировать элемент по `uuid`; `blockmerge.js`: сохранять BOM** | Патчи перенесены 21.10.2026 после независимой проверки на фикстурах: до — падение загрузки на `<Configuration>`, «Имя реквизита … не уникально», 34 ложных отличия `.bsl` из-за BOM (`config/update/merge-objects.md`, `config/update/merge-modules.md`) |
| 38 | **Инвариант дельты: перечень доработок не меняется от обновления**; исключение — объект удалён поставщиком (удалить + отчёт); «снят, но не изменён» — вернуть на поддержку | Правило и инструмент `config/update/delta-check.js` (проверено на 6 сценариях демо-набора: потеря, рост расхождения, удаление, свои объекты) — `config/update/delta-invariance.md` |
| 39 | **Несколько поставок в `.bin` — штатная ситуация** (главная поставка первой, `flag=0` обеим, копии `*.cf` обеих обязательны); прежнее ограничение «в `.bin` только одна поставка» снято как ошибочное | Проверено 28.10.2026 на 8.3.27.1859: три варианта двухпоставочного `.bin` загрузились exit 0, `.bin` после цикла байт-в-байт, с `flag=0` обе копии на месте — `config/supply/deliveries.md` |
| 40 | **Порядок поставок задаётся смыслом, а не историей**: главная (совпадение `name`+`version` с `Configuration.xml`, страховка — вендор продукта) идёт первой | Решение владельца 28.10.2026; в базе проекта «своей» поставкой исторически был модуль-дополнение — `config/supply/which-is-main.md` |
| 41 | **Инвариант поставок: ни один поставщик не теряется.** Сколько поставок было, столько осталось; менять можно только порядок (главная — первой) | Проверено 28.10.2026 на 8.3.27.1859: дерево с однофирменным `.bin` (1 поставка) поверх базы с 2 поставками — exit 0, 0 сообщений, после выгрузки `count = 1`, SHA1 совпал с одноставочным исходником. Правило — `config/update/deliveries-invariance.md` |

| 42 | **Уровни поддержки в собранной конфигурации — только `0`/`1`** | Прежний проход «level2» расширял статус корня на всё поддерево: в сборке 2.5.27.98 это дало 8 230 записей уровня `2`, из них 5 478 — дети объектов, стоявших в базе заказчика на `0`. Такие объекты выпадают из автообновления поставщика. Инструмент `config/supply/support-levels.js` считает уровни по SHA1 против дерева поставки (результат: 159 839 / 115 / 0), гейты 17/18. Проверено 28–29.10.2026 |
| 43 | **Устаревшая инструкция проекта не отменяет проверенный факт.** Сборка с одной поставкой «потому что 1С не принимает две» — ошибка: причина была в старом `traps.md` §5 и в проектных промтах | Эксперимент 28.10.2026 (8.3.27.1859): `.bin` с двумя поставками грузится и сохраняется байт-в-байт. Введены R20 (состав задаёт исходник, гейт до загрузки) и R21 (приоритет проверенного факта; расхождение — стоп и правка инструкции). Правила — `config/rules.md`, `config/update/deliveries-invariance.md` §5.1, `config/update/traps.md` п.17 |
| 44 | **Уровни для нескольких поставок: каждая запись — только против своей поставки.** Уровень главной поставки на записи второстепенных не переносится; у общего объекта допустим `0` в одной записи и `1` в другой. «Висячая» запись → `1`, запись без имени в `ConfigDumpInfo` блокирует `--write` | Предложение «наследовать уровень главной» отклонено: `0` означает паритет с *этой* поставкой и разрешает 1С заменить файл её копией без вопроса; у общего объекта наш файл — версия главной, значит паритет ложный. Инструмент `config/supply/support-levels-multi.js`: ЕРП 159 839/115/0, модуль 7 079/3 783/0 (из 4 565 общих записей 3 598 — `1`); идемпотентность 0, `bin_diff` — только уровни. Проверено 29.10.2026, 8.3.27.1859 — `config/supply/support-levels.md` §3.1, §7.2 |
| 45 | **Уровни считаются на `.bin`, в котором уже все поставки** (гейт 14), а не на одноставочном промежуточном файле | Первая версия инструмента требовала ровно одну поставку: результат собрался из одноставочного `.bin`, вторая поставка молча исчезла, при этом загрузка, `CheckModules` и приёмка ошибок не дали. Инвариант состава проверяется до расчёта уровней — `config/update/deliveries-invariance.md` |

## Выводы (не повторять)

- Возврат удалённых поставщиком объектов «для совместимости» даёт 1078 несоответствий планов.
- Слияние типов по номеру блока XML ломает формы (`Неверный путь к данным`).
- Копирование объектов ЕРП из поставки модуля — дубли `InternalInfo`.
- `-disableSupport` закрывает путь `.cfu` безвозвратно.
