# Файлы конфигурации: `.cf`, `.cfu`, `.dt`

| Расширение | Что это | Как использовать |
|---|---|---|
| `.cf` | полная конфигурация (вся метаданные + модули) | `/LoadCfg` в пустую базу; `/DumpCfg` — обратная операция |
| `.cfu` | обновление (дельта к версии-предшественнику) | `/UpdateCfg` на базе **той же** конфигурации нужной версии; не грузится в пустую |
| `.dt` | выгрузка **базы с данными** (демо/резерв) | `CREATEINFOBASE` + «Загрузить информационную базу»; это не конфигурация |

## Практика

- Поставка 2.5.27.98 пришла как `1cv8.cf` (+ `.cfu`). Цепочка `.cfu` поддерживает переходы с 2.5.26.118,
  2.5.27.82 и др., но **не с 2.5.22.186** — обновиться с текущей версии одним `.cfu` нельзя.
- `.dt` в поставке — демонстрационная база **с данными**; использовать её для контрольной загрузки
  «пустой базы» нельзя (получите чужие данные и 6 проблемных объектов). Решение: контроль — в пустую базу.
- `.cf` можно получить выгрузкой из базы (`/DumpCfg`), в т.ч. после ручного включения поддержки.

## Размеры (пример проекта)

| Файл | Размер |
|---|---|
| `current_2_5_22_186.cf` | 3,8 ГБ |
| `vendor_ERP_2_5_22_186.cf` | 2,26 ГБ |
| `update ERP_2_5_27_98.cf` | 1,5 ГБ |
| `vendor_UAT_2_5_21_1.cf` | 27 МБ |
| собранный результат (ERP .98 + модули) | ~1,53 ГБ |

## Что фиксировать при передаче

- имя файла, размер, **MD5** (`Get-FileHash -Algorithm MD5`);
- проверки: `LoadConfigFromFiles` (EXIT), `CheckModules` (EXIT + текст), `DumpCfg` (EXIT), `LoadCfg` в пустую
  базу (EXIT);
- версию конфигурации (`Configuration.xml → <Version>`) и версии модулей-поставщиков.
