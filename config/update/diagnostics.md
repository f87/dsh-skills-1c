# Диагностика: сообщение загрузки → причина → лечение

## Правило №1

**Ровно 200 строк в логе** и время 1–2 мин — 1С прервала загрузку по лимиту сообщений. Смотрите не
последнюю ошибку, а **классы**. Цикл: починили класс → перезагрузка (1–2 мин), пока не начнёт проходить
валидацию; успешная загрузка — 38–49 мин.

## Таблица

| Сообщение | Причина | Лечение |
|---|---|---|
| `Файл объекта не существует <путь>.xml` | ссылка на форму/макет/объект без файла | `syncobjfiles.js`; `fixconfig.js` (ChildObjects без файла) |
| `Неверный путь к данным` | в форму вставлен `<Type>`/элемент из чужого блока | не сливать составы типов по блоку; проверить `objmerge` |
| `Неизвестный объект метаданных - X` | ссылка на удалённый/переименованный объект | `multirename2.js`, `prunerefs.js`; единичные — в отчёт |
| `Неизвестное имя типа - DocumentRef.X` | состав типов ссылается на удалённый объект | `prunetypes.js` |
| `Недопустимый тип` | тип из чужой версии/блока | то же |
| `… не является регистратором для регистра` | новый регистр без документа-регистратора | `addregrec.js` |
| `Тип предопределенного вида характеристики не соответствует типу плана` | восстановлены удалённые объекты / слиты типы | не восстанавливать удалённые; вернуть версии поставщика |
| `Имя реквизита или поля X не уникально` | дубль реквизита с тем же UUID | удалить дубль, переименовать ссылки |
| `Дублирование имени объекта метаданных` | `>Имя<`-замена переименовала `<Name>` | не заменять `>Имя<` по всему дереву |
| `Тип порождаемый объектом InternalInfo содержит не уникальное значение` | скопирован объект другой конфигурации из поставки модуля / переименованный объект | копировать только по UUID-принадлежности |
| `объект метаданных Configuration не был загружен, поскольку не является подчинённым` | в `ChildObjects` попал `Configuration.*` | фильтровать имена в `addchild` |
| `Файл не содержит доступных обновлений` | `MergeCfg`/`UpdateCfg` после `-disableSupport` | путь `.cfu` закрыт, использовать `.cf` |
| `Информационная база не обнаружена!` | `CREATEINFOBASE` не сработал (в каталоге нулевые `1Cv8.1CD.cfl`) | удалить каталог базы, создать заново; форма строки — `"File='<ib>'"` (`1cv8/cli-gotchas.md`, п.8) |
| Ошибка разбора `Ext\ParentConfigurations.bin` (или «неверный формат» при загрузке) | побились кавычки/BOM/переводы строк в `.bin` | откатить файл; править только `config/support-state.ps1` (`config/support-state.md`) |
| «Несовпадение версии», инкрементальные ошибки загрузки | устаревший `ConfigDumpInfo.xml` | удалить/переименовать его — но проверено: полная `LoadConfigFromFiles` работает и с устаревшим реестром (`config/dump-to-xml.md`) |

## Ошибки, которых в логе НЕ будет

Потеря состава **определяемых типов** не даёт ошибки загрузки: конфигурация грузится и компилируется, а
проблема проявляется при реструктуризации непустой базы и видна в «Сравнить конфигурацию» как `<--`.
Поэтому в приёмке — отдельная проверка `mergetypes.js` (`defined-types.md`, `acceptance.md`).

## Порядок разбора

1. Классифицировать сообщения (`Select-String` по таблице), взять самый массовый класс.
2. Найти источник в дереве (поиск строки/имени по XML/BSL).
3. Починить **скриптом в дереве**, перезапустить сборку с нуля (детерминизм).
4. Повторять до нуля классов; затем полный прогон, `CheckModules`, `DumpCfg`, контрольная загрузка.

## Признаки «правильного» лога

- `EXIT 0`, 3–30 строк;
- только «Возможно неверная ссылка … внутри справки» (и для модулей — единичные «Неизвестный объект
  метаданных» для переименованных реквизитов, перечисленные в отчёте);
- ни одной строки из таблицы.
