# Сведение типов данных и составные типы (ОпределяемыеТипы)

## Критическое правило

**Состав определяемого типа = объединение с приоритетом текущей конфигурации.**

- Все типы, заявленные в текущей конфигурации (конфигурации базы данных), сохраняются **обязательно**.
- Новые типы поставщика (объекты, появившиеся в новой версии) добавляются **в конец**.
- Порядок — как в текущей конфигурации (минимум отличий при сравнении).
- Переименования поставщика учитываются по UUID: тип переписывается на новое имя
  (`Document.Бронирование` → `Document.ОперацияСЭлектроннымБилетом`).
- Если объект удалён и замены по UUID нет — тип **не добавляется**, попадает в отчёт `missing`;
  решение принимает человек.

## Почему это не косметика

`РегистрСведений.НаличиеФайлов.Измерение.ОбъектСФайлами` имеет тип `ОпределяемыйТип.ВладелецПрисоединенныхФайлов`.
Удаление типа из состава = потеря допустимых ссылок и **провал реструктуризации базы с данными**.
На **пустой** базе (которой проверяют `.cf`) ошибка не проявляется — поэтому «загрузилось» не является
доказательством.

## Инструмент

`config\update\mergetypes.js` (данные переименований — `..\_work\lists\removed_renames_ok.json`, `uat_erp_renames.json`):

```powershell
# отчёт без изменений
node config\update\mergetypes.js <resultTree> <currentTree> <report.json>
# применить
node config\update\mergetypes.js <resultTree> <currentTree> <report.json> --apply
# контроль после применения: addedFromCurrent = 0
```

Свойства: идемпотентен по содержимому, без дублей, XML остаётся валидным; переименования по UUID;
несуществующие объекты — в `missing`; блок `<Type>` **не перезаписывается** — только дописываются
недостающие `<v8:Type>` (см. ниже).

### Грабли реализации (исправлено 21.10.2026)

Два дефекта в `mergetypes.js`, которые ломали сборку незаметно на пустой базе:

1. **Перезапись блока `<Type>` целиком.** Скрипт собирал новый блок только из `<v8:Type>` и терял
   квалификаторы (`<v8:StringQualifiers>`, `<v8:NumberQualifiers>`, `<v8:DateQualifiers>`). В логе загрузки:
   **86 «Недопустимый тип»** и **200 «Неверный путь»**. Правильно — дописывать недостающие `<v8:Type>`
   после последнего, тело блока не трогать; для добавляемых примитивов (`xs:*`) переносить квалификаторы
   из текущей конфигурации.
2. **Неполная карта «суффикс типа → каталог».** Не было `DocumentObject`, `CatalogObject`, `*Selection`,
   `*RecordSet`, `*RecordKey` — такие ссылки считались валидными без проверки и попадали в состав,
   указывая на отсутствующие объекты (12 типов). Итог — те же «Неверный путь» при открытии форм.

Проверка после правки: `node --check`; dry-run (`addedFromCurrent = 0`); юнит-тест на одном `DefinedType`
с `xs:string` и квалификаторами — блок обязан сохранить `<v8:StringQualifiers>` после `--apply`.

## Составы типов ПВХ/планов/регистров

**Не сливать «по номеру блока»** — порядок блоков между версиями не совпадает, вставка попадает в чужой
состав и ломает загрузку (`Неверный путь к данным`, `Недопустимый тип`). Оставлять версию поставщика,
«мёртвые» ссылки чистить:

```powershell
node config\update\prunetypes.js <tree>   # <v8:Type>cfg:X.Y</v8:Type> на отсутствующий объект
node config\update\prunerefs.js  <tree>   # <xr:Item>/<xr:Object> на отсутствующий объект
```

## Приёмка

1. `mergetypes.js` без `--apply`: `addedFromCurrent = 0`, `missing` объяснён.
2. В 1С «Конфигурация → Сравнить конфигурацию» с базой по определяемым типам **нет** строк `<--`
   (тип только в конфигурации БД).
3. Только после этого — `DumpCfg` и передача.

## Что нельзя

- Брать типы «версией поставщика» (именно так потерялись 890 типов).
- Пересобирать блок `<Type>` целиком: теряются квалификаторы → «Недопустимый тип» (`defined-types.md`, грабли реализации).
- Удалять тип, если объект помечен `Удалить…`: пока объект существует, ссылки валидны.
- «Восстанавливать» удалённые поставщиком объекты ради ссылок: проверено — даёт 1078 несоответствий
  предопределённых планов; правильный путь — чистка ссылок.
