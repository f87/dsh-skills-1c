# Отчёты и передача результата

## Обязательный комплект

| Файл | Содержимое |
|---|---|
| итоговый отчёт `Отчёт_о_сборке.md` | для пользователя: что собрано, версии, размеры, MD5, проверки, как применять, ограничения |
| журнал сборки `build_log.md` | этапы, команды, время, EXIT-коды, ключевые наблюдения |
| `broken_refs.md` | ссылки на удалённые/переименованные метаданные, причина, границы проверки |
| `roles_check.md` | состояние ролей и прав на добавленные объекты |
| отчёт по типам `types_*.json` | сколько типов добавлено и сколько потеряно (`config/update/defined-types.md`) |

## Что фиксировать обязательно

1. Размер и **MD5** каждого `.cf`. Оговорка: MD5 `.cf` **не воспроизводим между базами** — две базы из
   одного дерева дают разные MD5 при идентичном содержимом (проверено 20.10.2026); фиксируйте MD5 вместе
   с датой и базой сборки, а конфигурации сравнивайте по XML и `ParentConfigurations.bin`.
2. Время и EXIT-код каждой операции (загрузка, `CheckModules`, `DumpCfg`, контрольная загрузка `.cf`).
3. Число предупреждений и их классы.
4. **Результат проверки определяемых типов** (`addedFromCurrent = 0`) — иначе сборка недействительна.
5. Что не сделано и почему (поддержка не сохранена; допустимые предупреждения; права на объекты).
6. Команды воспроизведения (скрипты сборки).
7. **Состояние поддержки** до/после: флаг конфигурации и распределение уровней (`0/1/2`), список объектов
   с уровнем 1/2 и причина; для возвращённых на поддержку — подтверждение `support-state.ps1 -Compare`
   (0 отличий от поставки). Источник — [`config/support-state.md`](../config/support-state.md).
8. Что проверялось по `.bin`: совпадение `Ext\ParentConfigurations.bin` после обратной выгрузки (да/нет).
9. **Числа состояния поддержки** (флаг и распределение `0/1/2`) — брать из **финального** `.bin`, а не из
   промежуточных отчётов, и привязывать к build-id (MD5 CF + SHA1 `.bin`). Если число в отчёте расходится
   с финальным `.bin` — правильным считается `.bin`, отчёт исправляется, а не наоборот.

## Передача пользователю

- `.cf` несёт состояние поддержки (дескриптор + уровни), но «на поддержке» только побайтно совпадающие
  с поставкой объекты; полное включение — вручную (`config/support.md`).
- Права на добавленные объекты — отдельными ролями (в ролях поставщика их нет).
- Обновление базы с данными выполняет пользователь; миграции — штатная реорганизация.
- После обновления БД проверить: уникальность записей регистров, `ОпределяемыйТип.ПрисоединенныйФайл`,
  открытие ключевых форм УАТ/ЭПД, форму `НаличиеФайлов`.
- Не удалять логи до приёмки — это доказательства проверок.
