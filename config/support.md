# Поддержка поставщиков: поставить, снять, два родителя

Универсальные сведения + практика на примере ERP 2.5.27.98 и модуля УАТ 2.5.22.1 (платформа 8.3.27.1859).

Формат `.bin` и поштучные процедуры правки выгрузки — [`support-state.md`](support-state.md).

---

## 1. Где хранится поддержка

| Где | Что |
|---|---|
| данные конфигурации (в базе) | полное состояние поддержки: родители, уровни объектов |
| `Ext\ParentConfigurations.bin` (в XML-выгрузке) | **то же состояние в текстовом виде**: по каждой поставке — версия/вендор/имя, флаг «изменения запрещены» и уровень для каждого объекта |
| `ConfigDumpInfo.xml` | `uuid → имя объекта`, чтобы читать `.bin` |
| `Ext\ParentConfigurations\<ИмяПоставки>.cf` | копия конфигурации поставщика (есть, когда не полная поддержка); число файлов = число поставок, выгрузка в XML и дельта — [`vendor-configs.md`](vendor-configs.md) |

В XML **объектов** (`Catalogs\*.xml` и т.п.) признака поддержки нет — только в `.bin`.
Поэтому «снять/поставить поддержку» в выгрузке = правка `.bin`, а не XML объектов.
Проверено: две выгрузки одной конфигурации, отличающиеся только поддержкой, совпали по всем файлам объектов.

## 2. Способы изменить поддержку

| Способ | Когда |
|---|---|
| Конфигуратор: `Конфигурация → Поддержка → Настройка поддержки` | обычная работа, интерактивно |
| Правка дерева: [`support-state.ps1`](support-state.ps1) | пакетно, воспроизводимо, без UI; состояние переживает `LoadConfigFromFiles` (проверено) |
| CLI `-disableSupport` | только когда поддержка больше не нужна совсем (см. §5) |

## 3. Постановка поддержки (Конфигуратор)

1. `Конфигурация → Поддержка → Настройка поддержки → Включить поддержку`.
2. Указать `.cf` поставки, выбрать правило поддержки объекта.
3. Для второго поставщика повторить — поддержка добавляется поверх первого.
4. Проверить: в «Настройке поддержки» видны все родители с ожидаемыми версиями.

Через файлы: объект ставится на поддержку (уровень 0), только если он **побайтно** совпадает с поставкой —
проверка `support-state.ps1 -Compare <vendor tree>`, затем `-Level 0`.

## 4. Контроль «правильного родителя»

В заголовке `.bin` каждой поставки есть тройка `"<версия>","<вендор>","<имя>"`. Она должна совпадать
с файлом поставки в `Ext\ParentConfigurations\`. Примеры (проект ERP):

- ERP 2.5.27.98 → `"2.5.27.98","Фирма ""1С""","УправлениеПредприятием"`;
- УАТ 2.5.22.1 → `"2.5.22.1","Фирма ""1С-Рарус""","МодульУправлениеАвтотранспортомДля1СERP"`.

Если остался дескриптор старой версии — поддержка включена на старую поставку, это ошибка.
Проверить все поставки: `support-state.ps1 -Tree <tree>` печатает имя/версию/вендор по каждой.

## 5. `-disableSupport` и тупик с `.cfu`

```powershell
& $exe DESIGNER /F"<ib>" /ManageCfgSupport -disableSupport -force /Out"<log>" /DisableStartupDialogs /DisableStartupMessages
```

**Осторожно:** после этого `MergeCfg`/`UpdateCfg` отвечают «Файл не содержит доступных обновлений» —
путь обновления через `.cfu` закрыт. Проверено на практике. Снятие поддержки «на один раз» лучше делать
правкой уровня объекта (1 или 2), а не `-disableSupport`.

## 6. Два родителя (пример: ERP + УАТ)

- Поддержка включается последовательно: сначала ERP 2.5.27.98, затем УАТ 2.5.22.1 поверх.
- В `.bin` тогда **две поставки** (поле «количество поставок» = 2), каждая со своим списком объектов.
- Объекты могут встречаться в обеих поставках; уровень ставится в записи той поставки, к которой относится
  uuid из `ConfigDumpInfo`. Скрипт обрабатывает многовыгрузку и показывает поставку в колонке `Delivery`.
- При обновлении поставки версии в заголовке меняются; старый дескриптор в дереве = поддержка на старую версию.
- Порядок поставок и флаги при сборке `.bin`, какая поставка главная, приёмка результата —
  [`supply/README.md`](supply/README.md).

## 7. Почему собранный `.cf` бывает «без поддержки»

Если дерево собиралось из файлов разных поставок (слияние), объекты не совпадают с поставкой побайтно,
и поставить их на поддержку нельзя — только уровни 1/2 («редактируется»/«снят»). Полная поддержка
возвращается либо после возврата объектов к версии поставки, либо вручную в Конфигураторе.
Это ограничение метода сборки, а не дефект `.cf`.
