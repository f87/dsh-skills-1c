# Доказуемое соответствие поставке: аудит отличий

Цель: к моменту передачи CF **каждое** отличие результата от поставки объяснено — либо это наша
осознанная доработка, либо исправленный дефект слияния. «Загрузилось» и «компилируется» этого не
доказывают.

Инвариант состава доработок — [`delta-invariance.md`](delta-invariance.md); здесь — пофайловый аудит.

---

## 1. Что проверяется

| Проверка | Инструмент | Критерий |
|---|---|---|
| Отличия от поставки по файлам | `checkvendorchanges.js` | `missing = 0`, `unexpectedModified = 0`; все `modified` — из ожидаемого списка |
| Определения метаданных (`<Name>`) не потеряны/не переименованы | `checknames.js --all` | `lost = 0`; `extra` объяснены |
| `Predefined.xml` | `checkpredefined.js` | `lost = 0`, `duplicateIds = 0`, `orphanNames = 0` |
| Дубли/обрывы процедур, баланс маркеров | `checkprocs.js` | `issues = 0` (с учётом базы) |
| Diff с предыдущей сборкой | `diffbuilds.js` (два manifest) | известный набор отличий, каждая причина названа |
| Архив артефактов | вручную/скриптом | CF + manifest SHA1 + списки + отчёты сохранены |

## 2. Порядок

1. **Ожидаемый список отличий.** Сформировать заранее: какие объекты/файлы мы намеренно меняем
   (результат слияния, переименований, объединения типов). Формат — список относительных путей,
   по одному в строке (его же использует `checkvendorchanges.js`).
2. **Хэш-диф с поставкой**: `node config\update\checkvendorchanges.js <result> <vendor> <expected-files> <report.json>`.
   - `missing` — в поставке есть, в результате нет: потерян объект или файл;
   - `unexpectedModified` — отличается, но не заявлен: рост расхождения или дефект слияния.
3. **Имена**: `node config\update\checknames.js --all <result> <vendor> <report.json>` — после любых
   переименований (`renamerefs.js`) определения не должны исчезнуть.
4. **Предопределённые**: `node config\update\SSL\checkpredefined.js <result> <vendor> <report.json>`.
5. **Процедуры**: `node config\update\checkprocs.js <result> <base>` — новые дубли/обрывы/маркеры.
6. **Diff сборок**: manifest SHA1 двух сборок → `node config\update\diffbuilds.js <prev.json> <curr.json> <report.json>`;
   каждое отличие — в отчёт с причиной.
7. **Архив**: до пересборки сохранить CF, manifest, списки и отчёты (папка вида
   `CF\history\<timestamp>\`). Без архива diff следующей сборки невоспроизводим.

## 3. Классификация отличий (обязательная)

Каждое отличие попадает в одну из категорий, иначе CF не принимается:

| Категория | Что это | Действие |
|---|---|---|
| Наша доработка | осознанное изменение из `current`/модуля | в отчёт, в ожидаемый список |
| Исправление дефекта слияния | артефакт (маркер, переименование, дубль) | устранить, пересобрать |
| Изменение поставщика | новая версия отличается сама | в отчёт как «поставка» |
| Потеря | `missing`/`lost` | блокер, чинить |

## 3.1. Гейт, который не смог проверить, — не успех

Отдельный класс ошибок — **эвристические гейты**, которые не нашли проблему и вернули «0», хотя на самом
деле ничего не проверили (пример: поиск ссылок только строкой `"Документ.X"`, тогда как в модуле
используется `Списки.Вставить(Метаданные.Справочники.X, Истина)`).

Правило: такой гейт обязан сообщать неопределённость отдельным кодом (например, `EXIT 2` — «строковых
ссылок нет, нужна ручная проверка») и не считаться пройденным, пока ручная проверка не выполнена.
«0 найденных проблем» без пройденной проверки — не результат.

## 4. Почему не доверять «зелёной» загрузке

- `CheckModules` не ловит пустые модули-заглушки, дубли `<Item id>`, переименованные определения и
  потерю правок, если результат компилируется ([`traps.md`](traps.md), п. 13);
- загрузка в пустую базу не запускает обработчики обновления — расхождения плана обмена и
  предопределённых проявляются только на базе с данными;
- сравнение «размеров» объектов (грубая эвристика) не видит семантических изменений — нужен хэш-диф.

## 5. Минимум для передачи

1. `delta-check.js` — `lost = 0`, `new = 0` ([`delta-invariance.md`](delta-invariance.md)).
2. `checkvendorchanges.js` — `missing = 0`, `unexpectedModified = 0`.
3. `checknames.js --all` — `lost = 0`.
4. `checkpredefined.js` — `duplicateIds = 0`.
5. `checkprocs.js` — `issues = 0`.
6. `LoadConfigFromFiles` EXIT 0, `CheckModules -ThinClient -Server` EXIT 0
   ([`config/checkmodules.md`](../checkmodules.md)).
7. `DumpConfigToFiles` → `Ext\ParentConfigurations.bin` побайтно совпал
   ([`support-state.md`](../support-state.md)).
8. Отчёт с таблицей отличий и причин — [`../other/reports-handover.md`](../../other/reports-handover.md).
